разблокированным был user 10. Pilot v2 зарегистрирована только в user 10;
Preview до каждой попытки отсутствовала. Свежий статус после последнего STOP
не запрашивался.

## Ответы на диагностические вопросы

| Вопрос | Вывод и предел доказательства |
|---|---|
| Требовалось ли подтверждение на экране? | **PROBABLE** по историческому поведению этого POCO. Показ, профиль и видимость окна 27 октября — **UNKNOWN**. |
| Есть ли запрет установки у user 10? | В обоих сохранённых preflight effective restrictions только `no_sms` и `no_outgoing_calls`; per-user и global device-policy restrictions — `null`. Запрет установки в этих блоках не обнаружен. Default restrictions других типов пользователей не относятся к user 10. Отдельную проверку Xiaomi это не исключает. |
| Отклонила ли установку защита производителя? | Для попыток 22 октября — **PROVEN**, для Preview 27 октября — **PROBABLE**. Нет текущего журнала, связывающего именно эти ошибки с OEM-проверкой. |
| Есть ли связь с ADB? | Исторически доказана цепочка проверки установки из shell. В текущих командах явно задан user 10 и правильный APK; ошибка выбора пакета/целевого пользователя не обнаружена. `--user 10` не гарантирует профиль OEM UI. |
| Можно ли полностью объяснить отказ без телефона? | Можно обосновать вероятный механизм и риск user 0. Отличить ручной отказ, тайм-аут, недоступность окна и иное внутреннее OEM-правило по имеющимся данным нельзя. |

Строка `Install canceled by user` — текст системного результата, **не доказательство
нажатия владельцем «Отмена»**. Перед двумя попытками не был выполнен явный обмен
«посмотри на экран → я уже у телефона → начинаю сейчас». Это недостаток процедуры
агента; его причинная связь с отменой не доказана. Ответ о готовности произнести
речь не подтверждал готовность наблюдать установочный диалог.

## Отдельное историческое свидетельство: 22–23 октября

Сохранённые исходные логи от 22 октября подтверждают цепочку:

`PackageManagerServiceImpl.verifyInstallFromShell → PmInjector.installVerify → com.miui.securitycenter/com.miui.permcenter.install.AdbInstallActivity`.

В обеих попытках ActivityTaskManager записал **START u0**, caller UID 1000;
проверка целостности перед этим прошла. Затем появились
`Failure [INSTALL_CANCELED_BY_USER]`, `Install canceled by user` и отказ сессии

## Недостающие доказательства и минимальное продолжение

Нужны связанные с попытками 27 октября installer-события: вызов/результат OEM
проверки, профиль и жизненный цикл окна, причина отказа внутри проверки. Для
доказательства нажатия нужна отдельная достоверная запись действия или сообщение
владельца; по коду ошибки это не восстанавливается.

Следующие шаги **предлагаются, но не выполняются и этим документом не разрешены**:

1. После нового отдельного допуска только на read-only диагностику проверить
   сохранность ограниченных installer-событий и session metadata предыдущих
   попыток на устройстве. Не запускать установку для воспроизведения, не очищать
   logcat, не собирать полный bugreport, экран или данные приложений. Ограничить
   сбор нужными временами и installer-компонентами, raw результаты оставить локально.
   Если события уже вытеснены, зафиксировать отсутствие; не создавать новую попытку.
2. Если журналы не дают ответа, предложить отдельный ручной осмотр владельцем
   доступных в **существующем user 10** страниц подтверждения USB-установок: сообщить
   точный текст и состояние, ничего не переключая. Предварительно отправить
   **🔔 ТРЕБУЕТСЯ УЧАСТИЕ ЮРИЯ**, описать страницы и оценку 2–3 минуты, затем ждать
   явного разрешения и готовности. Не открывать user 0, аккаунты или административные
   экраны. Если осмотр без них невозможен — STOP. Scrcpy этим шагом не разрешён.
3. По новым данным описать конкретный путь подтверждения в user 10. Если он требует
   user 0 или изменения защиты, оставаться BLOCKED в текущих границах. Не отключать
   проверки и не предлагать переключение пользователей как автоматическое исправление.

Лишь если безопасный путь установлен, подготовить **одну** попытку с тем же package,
SHA-256 и target user 10, точным ожидаемым диалогом и stop-условиями. До любых новых
команд телефону согласовать полный ограниченный набор preflight/install/postflight
действий. Затем отправить уведомление и ждать именно
**«РАЗРЕШАЮ ОДНУ УСТАНОВКУ. Я У ТЕЛЕФОНА».** После ответа объявить
**«НАЧИНАЮ СЕЙЧАС. СМОТРИ НА ЭКРАН POCO».** Выполнить один согласованный вызов;
неожиданный запрос — STOP, без retry. Success требует допущенной проверки установки
только для user 10 и точного APK, а не автоматического перехода к записи/ASR.

Участия владельца потребуют ручной осмотр, наблюдение и подтверждение известного
установочного окна, а при последующем отдельно разрешённом тестировании — каждое
новое разрешение, выбор файла и согласованный сигнал начала речи. Для каждого
такого этапа действует новый цикл уведомления и ожидания.
