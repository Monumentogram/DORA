## PCM envelope specification

Observed source: `recording/NativeMicrophone.kt` uses mono PCM16, 16,000 Hz.
`AudioRecordCapture.kt` reads up to 1,600 bytes (800 samples, about 50 ms), sends an
owned copy to `CaptureAdmission`, computes a scalar RMS at most every 50 ms, then
wipes its read buffer. `RecordingController` publishes presentation every 50 ms;
`DoraWave` draws a circular history. Merely drawing that scalar at 60 FPS cannot
recover short peaks or extra temporal detail.

Add `recording/visualization/PcmEnvelope.kt` with an internal
`PcmEnvelopeSink.offerPcm16(bytes: ByteArray, count: Int, epoch: Long): Unit` contract.
The caller owns the array; the method completes synchronously without retaining or
modifying it. The production sink performs only a bounded linear scan and primitive
publication. Disabled sink is a no-op. No disk, JNI inference, network, Compose,
dispatch-per-sample, coroutine suspension, blocking lock or allocation per sample.

Engineering defaults (tunable after the first POCO rendering check, not design facts):

1. Process **every fully accepted read**, not just reads selected by the existing
   RMS timer. Call the observer after admission accepts the owned audio copy and
   before wiping the independent read buffer. Preserve admission/fencing logic.
   `LIMIT_REACHED` may have admitted a final partial block: retain its existing
   immediate break and deliberately omit that last partial block from live graphics.
   Never display the unadmitted remainder or treat this graph as an audio integrity
   receipt. Test this boundary explicitly.
2. Decode signed little-endian PCM16 to Int before absolute value, so -32768 is
   handled correctly. Accumulate a 5-ms bucket (80 samples), carrying incomplete
   buckets across short reads. Keep `maxAbs`, sum of squares and sample count;
   RMS is optional secondary data, never the replacement for the peak envelope.
3. Stamp buckets by capture epoch and sample interval. Audio/sample time defines
   geometry; monotonic time is used only for freshness/render cadence. Wall-clock
   date, ASR clocks and model validity do not participate.
4. Publish peak buckets into a preallocated `AtomicLongArray` SPSC ring (2048
   buckets, about 10.24 s). Each slot is **one atomic packed word**: 48-bit monotonic
   bucket sequence plus 16-bit maxAbs (0..32768). Sequence does not reset across
   pause/epochs. Set the whole word, then publish the latest sequence via an
   AtomicLong. Consumer checks each atomically read word against the exact expected
   sequence; stale/overwritten slots cause a gap, never mixed fields. Do not use a
   multi-field payload followed only by a sequence write: overwrite can tear it.
   Keep epoch/start-sample metadata in one immutable descriptor published once per
   epoch; consumer accepts a snapshot only if that descriptor is unchanged before
   and after collecting words. RMS is not needed in this first visual ring. A
   bounded retry may skip a visual snapshot; it cannot stall the producer.
5. A low-priority visualization consumer drains off the audio thread. Ordinary
   60→30→20-FPS throttling aggregates all buckets in each display bin using **max**,
   never last-value or mean. A one-sample impulse must survive this aggregation.
   The consumer sends an immutable envelope snapshot to UI; it does not deliver
   PCM to the UI or share the persistence queue with another consumer.
6. If the visual consumer stalls beyond ring capacity, overwrite oldest visual
   history only and expose a sequence gap. Do not synthesize continuity, stop
   capture, or claim unlimited lossless visualization. Reset the displayed window
   on resume after a long background gap. The normal visible time window is shorter
   than ring capacity; ordinary frame throttling does not cause peak loss.
7. Reference window: 3.28 seconds at 164 bins (20 ms/bin). Re-bin using max over all
   intersecting buckets. At another width choose a bin count from available width
   and minimum stroke/gap; do not change audio sampling to force 164. Exact stroke,
   gap, height and direction await the reference frame; provisional time flows
   oldest left → newest right and is explicitly an engineering choice.
8. Normalize peak by 32768. For display use `clamp((20*log10(max(p,1e-4))+80)/80,0,1)`
   to reveal quiet signals. Silence draws a static baseline. No random jitter, gate
   that drops quiet speech, or auto-gain on the recorded PCM. Show the peak instantly;
   optional visual decay may trail it but cannot reduce a new peak's height.
9. `SignalWaveform` draws one Canvas, not 164 independently recomposing controls.
   Use frame callbacks while visible/authorized/RECORDING and fresh; update only
   drawing state. Existing timer/control state stays at its current cadence.
10. Start with at most 60 FPS if resources permit. A rolling window of frame misses
    or existing load/thermal state reduces the cap to 30, then 20; recover slowly
    after sustained healthy frames. Stop requesting frames when static or hidden.
    Thresholds are engineering tuning (initial: >10% missed frames over 2 s,
    recover after 5 healthy seconds), not a guaranteed POCO performance claim.
11. On pause request freeze immediately, then reflect confirmed PAUSED; discard
    stale epoch samples on resume. Stop, route loss, permission loss and unhealthy
    capture freeze graphics and show the real state. No moving display without
    incoming samples. No extrapolated microphone amplitude between samples.
12. Reduced motion disables scrolling/interpolation and uses a static bounded
    level/peak indicator at no more than 10 Hz. TalkBack announces state changes,
    never every peak. Keep >=48-dp controls and respect system animator settings.

The passive observer is the only planned modification inside the capture area.
It must not touch `NativeMicrophone` buffer configuration, the owned persistence
copy, `BoundedPcmQueue`, `CaptureAdmission`, pause/resume authority or service
ownership. Preserve zeroing. Failure/overload of visualization disables or skips
visual output, never changes the recorded sample stream or recording state. Catch
observer RuntimeException at the passive observation boundary and disable that
observer for the epoch; it must not escape into the existing read loop's catch
and become READ_ERROR. No repeated log/throw storm on the audio thread.

Do not start task 2 until task 1 is accepted; a small screen change should remain
independently reviewable. No new PR is created by this preparation task.

- [ ] Add `PcmEnvelopeTest`: PCM silence, -32768 clipping, quiet speech, one-sample

- [ ] Add `PcmEnvelope.kt`, `EnvelopeSnapshot.kt` and `SignalWaveform.kt`; expose the

## Review focus and explicit readiness boundary

Highest risks and owning checks: short impulses lost by sampling (task 2); stale
peaks after pause/background (2); audio corruption/backpressure from observer (2);
editing/active version lost on navigation (3); hidden automatic upload (4).

Stage10 capabilities **not implemented by this preparation**: Signal screens,
164-density horizontal envelope, adaptive FPS pipeline, product search/indexing,
advanced filters, unified recording library, new settings preferences. Existing
real Local/Cloud recognition and edits are not newly implemented features. No new
diarization, word timestamps, live transcript, summary/tasks or playback waveform
quality is claimed.

**PASS / SIGNAL_UI_IMPLEMENTATION_READY** means architecture, screen map, boundaries,
waveform algorithm and staged work are prepared from inspected source. It does not
mean implemented UI, exact Figma parity or measured 60 FPS. Figma quota blocks
retrieval of exact frame geometry/fonts/assets and visual acceptance, not this
architecture handoff. Follow up with the approved frames before pixel-level work.
