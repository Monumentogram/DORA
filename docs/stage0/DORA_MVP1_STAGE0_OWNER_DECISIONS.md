# Dora MVP 1 — решения владельца для ближайших PoC

Статус: **Ожидает прямых ответов владельца**
Дата: 4 августа 2026 года
Область: только блокеры ближайших Stage 0 PoC
Связанные записи: DEC-001–DEC-004, DEC-009, DEC-014, DEC-015, DEC-018, DEC-020, DEC-027

Этот список намеренно короче полного реестра из 42 решений. Ни один ответ ниже не считается `Approved`, пока владелец не пришлёт точную или равнозначную формулировку. Ответы фиксируются отдельным изменением Product Decisions/ADR; этот документ сам по себе ничего не утверждает.

## OD-01. Какой технический PoC запускать первым и что он вправе записывать?

**Простой вопрос:** подтверждаем ли первым `POC-CAPTURE-001`: изолированный тест микрофона, который запускается только явным нажатием и не записывает звонки, системный звук или фон без участия пользователя?

**Зачем это нужно:** capture — первый риск в порядке Technical Plan. Без точной границы PoC легко превратить в преждевременную product-функцию или проверить недостижимый Android-сценарий.

**Варианты:**

- A — первым запустить `POC-CAPTURE-001`; только физический микрофон и ручной Start/Stop.
- B — сначала выполнить безопасный синтетический `POC-SEARCH-001`, а capture отложить.
- C — включить system/call/passive recording; это отдельный product/legal track и не допускается текущим планом.

**Рекомендуемый вариант:** A.

**Последствия рекомендации:** следующий чат создаёт отдельный disposable PoC-harness с microphone permission и microphone FGS только в PoC-ветке. Код не поступает в production автоматически и не подтверждает поддержку всех телефонов.

**Без решения заблокировано:** начало `POC-CAPTURE-001`, а вслед за ним `POC-BATTERY-001` и production capture Stage 2.

**Точная форма ответа владельца:**

`OD-01: выбираю A — первым запускаем POC-CAPTURE-001; только физический микрофон, явный Start/Stop, без звонков, системного звука и passive recording.`

## OD-02. Как подтверждать уведомление участников в capture PoC?

**Простой вопрос:** нужен ли перед каждым тестовым запуском отдельный checkbox о том, что все участники предупреждены?

**Зачем это нужно:** Android permission подтверждает доступ приложения к микрофону, но не согласие людей на запись. PoC должен тестировать честный user-initiated flow, не выдавая checkbox за юридическое разрешение.

**Варианты:**

- A — обязательный короткий checkbox перед каждым запуском PoC.
- B — одно нажатие с кратким напоминанием без checkbox.
- C — только одно подтверждение при первом запуске.

**Рекомендуемый вариант:** A как временный PoC-контракт до Legal/usability review.

**Последствия рекомендации:** время старта будет немного больше; формулировка версионируется и явно говорит, что Dora не определяет законность записи.

**Без решения заблокировано:** capture-flow `POC-CAPTURE-001` и последующее проектирование production preflight.

**Точная форма ответа владельца:**

`OD-02: выбираю A — перед каждым тестовым запуском нужен отдельный checkbox; это напоминание, а не юридическое разрешение.`

## OD-03. Какие аудиоданные разрешены для Stage 0?

**Простой вопрос:** разрешаем ли только синтетический сигнал и специально записанные тестовые фразы взрослых добровольцев с отдельным согласием, без реальных совещаний?

**Зачем это нужно:** capture/VAD/ASR/diarization требуют воспроизводимого звука, но публичный репозиторий и текущий этап не допускают private meeting audio.

**Варианты:**

- A — синтетика сначала; специально записанные тестовые фразы только по отдельному consent-процессу; реальные совещания запрещены.
- B — только полностью синтетические данные; качество на живой речи пока не оценивается.
- C — разрешить реальные совещания; это требует отдельного legal/research процесса и сейчас не рекомендуется.

**Рекомендуемый вариант:** A.

**Последствия рекомендации:** ранние deterministic checks можно выполнять сразу; corpus quality PoC начнётся только после manifest, согласий, контроля доступа и удаления.

**Без решения заблокировано:** acoustic часть `POC-VAD-001`, `POC-ASR-001`, `POC-DIAR-001`, `POC-DECISION-001` и полноценная matrix capture fixtures.

**Точная форма ответа владельца:**

`OD-03: выбираю A — синтетика сначала; специально записанные тестовые фразы взрослых добровольцев только с отдельным согласием; реальные совещания запрещены.`

## OD-04. Можно ли использовать PoC-данные для обучения моделей?

**Простой вопрос:** подтверждаем ли полный запрет на обучение и улучшение моделей по Stage 0 данным без нового отдельного research consent?

**Зачем это нужно:** согласие на проверку функции не означает согласия на training, human review или повторное использование корпуса.

**Варианты:**

- A — обучение запрещено по умолчанию; нужен отдельный будущий research consent и новый purpose record.
- B — training разрешён тем же согласием, что и PoC evaluation.
- C — использовать только synthetic data и никогда не собирать purpose-recorded voice data.

**Рекомендуемый вариант:** A.

**Последствия рекомендации:** evaluation и product research остаются разделены; dataset нельзя позже незаметно переиспользовать для обучения.

**Без решения заблокировано:** утверждение consent form, access manifest и любое сохранение purpose-recorded test audio.

**Точная форма ответа владельца:**

`OD-04: выбираю A — Stage 0 данные нельзя использовать для обучения или улучшения моделей без отдельного будущего research consent.`

## OD-05. По каким порогам выносить pass/fail?

**Простой вопрос:** принимаем ли Gate Set v0.1 из `DORA_MVP1_POC_GATES.md` как критерии Stage 0, но не как публичные обещания продукта?

**Зачем это нужно:** без заранее зафиксированного правила один и тот же результат можно объявить и успехом, и провалом. Сейчас все числовые пороги имеют статус `Proposed`.

**Варианты:**

- A — утвердить v0.1 для Stage 0; critical data-loss/source/consent gates не ослаблять после просмотра результата.
- B — разрешить только baseline measurements без verdict; после них утвердить v0.2 и повторить тест.
- C — изменить конкретные пороги до первого запуска с письменным обоснованием.

**Рекомендуемый вариант:** A для уже определённых critical gates; если владелец не готов — B, но результат первого запуска будет только `inconclusive/baseline`, не `pass`.

**Последствия рекомендации:** отчёты становятся сравнимыми; прохождение означает только PoC evidence, а не admission production dependency или marketing claim.

**Без решения заблокировано:** authoritative `pass/fail` любого `POC-*`, прежде всего `POC-CAPTURE-001`.

**Точная форма ответа владельца:**

`OD-05: выбираю A — утверждаю Gate Set v0.1 только для Stage 0; это не обещание продукта, critical data-loss/source/consent gates не снижаются после просмотра результата.`

## OD-06. Какие физические устройства реально доступны?

**Простой вопрос:** подтверждаем или закупаем ли физические D1–D5 для полной capture-матрицы, отдельный D6-набор аудиомаршрутов, а D7 сначала допускаем на проверенном 16-KiB эмуляторе?

**Зачем это нужно:** emulator не воспроизводит реальную батарею, микрофон, OEM killing, flash и thermal behavior. Матрица требований не доказывает наличие телефона.

**Варианты:**

- A — подтвердить/обеспечить физические D1–D5, D6-телефон с нужными аудиомаршрутами и D7 16-KiB emulator; физический D7 нужен перед финальным native support claim.
- B — начать exploratory run только на одном подтверждённом D2; не выносить общий pass/fail.
- C — использовать только emulator; capture/endurance claims остаются заблокированы.

**Рекомендуемый вариант:** A. Если инвентаря пока нет — B только для настройки harness.

**Последствия рекомендации:** поддержка будет ограничена реально измеренной матрицей; после OTA критические сценарии повторяются.

**Без решения заблокировано:** полный `POC-CAPTURE-001`, `POC-RECOVERY-001`, `POC-BATTERY-001`, device-tier ASR/diarization и любые support claims.

**Точная форма ответа владельца:**

`OD-06: выбираю A. D1=<модель/firmware или unknown>, D2=<модель/firmware или unknown>, D3=<модель/firmware или unknown>, D4=<модель/firmware или unknown>, D5=<модель/firmware или unknown>; D6=<телефон и доступные audio routes или unknown>; D7=<16-KiB emulator/image или unknown>; неподтверждённые устройства имеют availability=unknown.`

## OD-07. Что обещать про восьмичасовую запись?

**Простой вопрос:** считаем ли восемь часов best effort только на проверенных устройствах и условиях?

**Зачем это нужно:** OEM, заряд, температура и свободное место не позволяют обещать одинаковый результат на каждом Android-телефоне.

**Варианты:**

- A — поддерживать 8 часов только на versioned tested matrix и при выполненном preflight.
- B — гарантировать 8 часов на всех поддерживаемых устройствах.
- C — исключить 8-часовой сценарий из MVP.

**Рекомендуемый вариант:** A.

**Последствия рекомендации:** PoC идёт ступенями 1→3→8 часов; провал сужает support matrix или требует fallback, но не скрытый workaround.

**Без решения заблокировано:** interpretation endurance results, `POC-BATTERY-001` и будущая product claim.

**Точная форма ответа владельца:**

`OD-07: выбираю A — восемь часов являются best effort только для проверенных устройств, firmware, питания, температуры и свободного места.`

## OD-08. Где хранить evidence PoC?

**Простой вопрос:** разрешаем ли в публичном GitHub только обезличенные схемы, агрегированные метрики и безопасные отчёты, а raw traces и любое аудио — только в контролируемом непубличном хранилище?

**Зачем это нужно:** репозиторий, PR и Actions logs публичны; traces могут раскрывать пути, серийные идентификаторы или content.

**Варианты:**

- A — GitHub только для sanitized evidence; raw evidence хранится encrypted/private с access log и opaque reference.
- B — загружать raw traces в GitHub Actions artifacts.
- C — хранить всё только локально без воспроизводимого manifest.

**Рекомендуемый вариант:** A.

**Последствия рекомендации:** публичный отчёт проверяем по digest/manifest, а чувствительный источник остаётся вне Git/LFS/Actions. Требуется назначить владельца controlled storage до первого sensitive run.

**Без решения заблокировано:** сохранение raw Perfetto/Batterystats/device evidence и любой purpose-recorded audio result.

**Точная форма ответа владельца:**

`OD-08: выбираю A — в GitHub только sanitized reports/metrics; raw traces и аудио только в контролируемом непубличном хранилище с access log, retention и удалением.`

## OD-09. Как долго хранить purpose-recorded test data?

**Простой вопрос:** принимаем ли начальный срок: raw audio до 90 дней после закрытия PoC, производные annotations до 180 дней, удаление после отзыва согласия не позднее 30 дней?

**Зачем это нужно:** до записи человек должен знать предельный срок. Бессрочное хранение «на всякий случай» запрещено принципом минимизации.

**Варианты:**

- A — принять 90/180/30 дней как Stage 0 default; более короткий срок имеет приоритет, если его требует consent/legal basis.
- B — указать другие точные сроки до сбора данных.
- C — использовать только synthetic data и не хранить записи добровольцев.

**Рекомендуемый вариант:** A как консервативный operational default до Legal review.

**Последствия рекомендации:** manifest получает `expiresAt`; retention job пока не реализуется, поэтому data custodian удаляет и документирует вручную.

**Без решения заблокировано:** сбор и хранение purpose-recorded audio, даже если согласие на саму запись получено.

**Точная форма ответа владельца:**

`OD-09: выбираю A — raw audio ≤90 дней после закрытия PoC, annotations ≤180 дней, отзыв согласия исполняется ≤30 дней; более короткий обязательный срок имеет приоритет.`

## OD-10. Что обязательно должно работать без account, сети и GMS?

**Простой вопрос:** подтверждаем ли local-first baseline: cloud выключено, account не нужен, а core PoC не зависит от Google Mobile Services?

**Зачем это нужно:** иначе network/auth SDK может незаметно стать обязательной частью локального ядра и исказить `POC-OFFLINE-001`.

**Варианты:**

- A — local mode без account/network/GMS; cloud только отдельным будущим consent.
- B — account требуется при первом запуске.
- C — hybrid/cloud включены по умолчанию.

**Рекомендуемый вариант:** A.

**Последствия рекомендации:** PoC harness использует local safe defaults и не добавляет remote config/analytics/provider SDK; cloud/VPN остаются отдельными поздними PoC.

**Без решения заблокировано:** итоговый gate `POC-OFFLINE-001` и admission любых network/account dependencies.

**Точная форма ответа владельца:**

`OD-10: выбираю A — local mode работает без account, сети и GMS; cloud выключено до отдельного явного consent.`

## Как зафиксировать ответы

Владелец может прислать десять строк `OD-01`–`OD-10` одним сообщением. Инженер затем:

1. переносит решения в `DORA_MVP1_PRODUCT_DECISIONS.md` с owner/date/status;
2. при необходимости создаёт ADR для технических последствий;
3. обновляет backlog и Stage Status;
4. только после этого открывает отдельную ветку первого PoC.
