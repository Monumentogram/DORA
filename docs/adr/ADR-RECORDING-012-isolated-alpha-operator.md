# ADR-RECORDING-012 — Isolated Alpha package and operator

Status: owner-authorized implementation, 2026-10-21; acceptance requires external exact-commit evidence. Base `1442f0db8a6936920a692913035d100f68871f81`. This decision supplements ADR-RECORDING-011 without closing physical or release gates.

Android Package Manager shares package code across users. A new build must therefore have runtime applicationId `com.monumentogram.dora.alpha.test`, in addition to a separately approved full Secondary User. Gradle `testApplicationId` alone would only rename instrumentation and is insufficient. Kotlin namespaces/classes remain stable. Production and `.debug` applicationIds are unchanged.

`alphaTest` inherits release security implementations. Its operator code and launcher are compiled only into that variant. The optional instrumentation signing property selects an emulator test certificate without enabling debuggability or development App Lock overrides. The physical candidate is signed outside Gradle with a separate locally generated key, never the production signing key. Real VAD packaging continues through the pinned private input gate; CI has no private model or signing material. Emulator synthetic adapter evidence and the real arm64 candidate are explicitly different artifacts.

The selected process uses its own Context app-private root and user/app UID Keystore namespace. No shared UID, cross-user permission, external vault root, migration or diagnostic acquisition of another package is introduced. Existing aliases remain string-identical where appropriate but resolve within different UID namespaces. AndroidX authorities and generated signature permissions follow the new applicationId. FGS, AudioRecord, VAD, Recovery, encryption, tombstones, canonical PCM and both recording/backpressure limits remain the accepted implementations.

The alpha-only operator requires an explicit user ID matching the actual process, a matching user serial, a host-confirmed full-secondary topology and an exact local RecordingId. Android public APIs cannot independently attest all full-secondary classifications on every supported API; operator-entered host confirmation is not a cryptographic attestation. The read-only host preflight independently checks the system user type and rejects owner, profile, guest, restricted, demo, disabled, ephemeral or ambiguous users. Invalid inputs fail closed and never become storage paths or another Context.

Authorized readback uses the ordinary runtime App Lock/session and OriginalAudioReference, requires durable completion and authenticates the complete contiguous canonical range. PCM is transient and cleared. A revocable, one-use, exact-reference/session proof enables a separate explicit delete action; actual deletion retains the existing user confirmation and lifecycle. Authenticated inspection checks the durable tombstone and absence of every recorded file/key deletion target. It does not claim physical flash overwrite. A partial or unverifiable cleanup cannot report success.

Required acceptance is the four inherited exact-SHA jobs (`alpha-contracts`, `alpha-software`, `alpha-encrypted-api28`, `alpha-encrypted-api36`) plus `isolated-alpha-software`, `isolated-alpha-api28`, and `isolated-alpha-api36`. Local real-VAD two-clean-build identity/payload evidence and independent review with no unresolved P0/P1/P2 remain mandatory. No receipt from an earlier source/APK is silently transferred to a changed candidate.

Future physical operations require a separate owner decision and the [isolated smoke protocol](../POCO_ISOLATED_ALPHA_PHYSICAL_SMOKE_PROTOCOL.md). Current software work authorizes no physical user creation, installation, launch, recording, PIN change or historical-vault access. Security restoration remains OPEN; Stage8.6 remains NOT_READY; LONG02 cause/protection and Signed Alpha remain unproven/uninstalled/not ready as previously recorded. Google Sheet is unchanged.
