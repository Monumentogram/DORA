# ADR-AUDIO-004 — Recording control latency and captured-time presentation

Status: implementation candidate; PENDING_FINAL_PUBLICATION. Parent: `c596f5256e34bebf308d4c90d89c9f97affc3abb`.

## Measured problem

The owner observed approximately two-second Pause/Resume delays and a captured-time label that skipped seconds. On the physical POCO, baseline Pause took 1.66–1.80 seconds. Native release took 80–141 ms; encrypted tail append took 1.56–1.66 seconds. The five-second append also blocked the worker that published captured frames and microphone amplitude. The owner's private video showed 14→16, 19→21 and 24→26 second jumps. No video, audio, device identifier or recording identity is included in source evidence.

## Decision

1. Publish truthful pending controls immediately. Confirm PAUSED only after the admission fence, native reader exit, owned queue drain and durable session pause. Confirm RECORDING only after authorization consumption, native recording and new physical-segment provenance. Pending notification controls follow the same state.
2. Serialize generation validation, bounded queue offer and the Pause fence under one short monitor. No native call, keystore, journal, disk or callback runs under that monitor. Every accepted PCM block remains owned by the recording until drained or a typed failure interrupts it. Stop/Pause during initial native startup or Resume cannot silently discard owned frames.
3. The reader owns release. A coalesced asynchronous native stop shares the native-ownership monitor with release; a queued old stop checks handle identity. Keep the 2000 ms join timeout. A delayed old reader prevents all new native starts. Service creation/destruction has synchronous opaque generation authority; queued work cannot revive a destroyed owner. Destroyed preparation is also retired.
4. A same-foreground Resume may consume the current AppLockSession.Authorization only with the exact active RecordingAccess, its epoch, the current recording action and live foreground-service owner. Recheck these at native start. Background, screen lock, recreation/restart or revocation cannot reuse the old grant. This adds no grace period, unlock cache, synthetic proof, revived writer or debug exemption. ADR-DEV-001 and its release behavior remain byte-identical.
5. The main-thread presentation tick reads only admitted frame counters and microphone amplitude. Captured time is sample-derived, never wall-clock extrapolation. Durable time remains the persistence worker's confirmed frame count. A blocked append therefore cannot freeze captured seconds or the waveform. Paused time is excluded; a recovered recording adds its restored frames to the new admission origin.
6. Preserve every SQLCipher policy checkpoint. Combine four policy values into one supported table-valued PRAGMA query and read `wal_autocheckpoint` separately. Require exact row/column cardinality and all original values; any drift permanently fences the helper. Actual SQLCipher device tests cover the combined query and policy drift. Do not cache run-key AEAD handles: cold-open validation is a mandatory failure boundary, including failure between bootstrap and publication. No durability, fsync, readback, Recovery reconciliation or catalog transaction is removed.

## Measurement and limitations

Debug-only, bounded content-free diagnostics retain monotonic touch time without an age cutoff, immutable operation association, admission boundary, native stages, auth route, first PCM, drain/tail stages and paired append spans. UI draw records retain Choreographer vsync; the external physical runner joins to `gfxinfo` DisplayPresentTime. Draw and state publication are not presented-frame evidence. Missing frame matches are retained as missing, never dropped from the denominator.

The first 20-pair run used the physical POCO with the development marker absent; the marker was restored after the test was saved and the microphone stopped. Same-foreground Resume needed no additional prompt. Capture admission p95 was 17.05 ms; native Resume 64.82 ms; first PCM 212.66 ms. Pause acknowledgement p95 was 109.60 ms (limit 100), confirmed durable Pause 2102.76 ms (limit 500). Three Resume confirmation frames had no exact presentation match, so that metric is INCOMPLETE, not PASS. The complete raw run is retained privately; public content-free values are in the remediation evidence JSON.

Captured timer presentation was observed for consecutive seconds with approximately 0.94–1.05 second intervals; no skipped seconds or two-second stalls occurred on that measured segment. This is bounded physical evidence, not a universal frame-rate guarantee.

**P1 remains open:** encrypted Pause tail persistence does not meet the required 500 ms p95. The fixed thresholds remain 100/250/500 ms for Pause acknowledgement/admission/confirmation and 100/500/750/750 ms for Resume acknowledgement/native/first PCM/confirmation. Exactly 20 values and nearest-rank p95 (19th sorted sample) are required. Source admission, unit tests and historical Stage 8.3 functional PASS cannot certify these physical thresholds.

Independent review found and the implementation corrected destroyed-service preparation ownership, stale failure across capture generations, and an authorization-cancel presentation ticker leak. The capture lifetime regression is deterministic; controller lifecycle retirement currently has static review rather than a directly injected controller race test. A separate physical background/return/Resume test used the fresh authorization route: auth completed at 4214.93 ms including human confirmation, native recording at 4263.28 ms, first PCM at 4399.16 ms. No native start preceded authorization. The test was saved, the microphone stopped, and the owner's development marker restored. Final exact-SHA CI, artifact audit and publication evidence remain separate gates. Stage 8.4 is NOT_STARTED; Stage 8 is IN_PROGRESS.
