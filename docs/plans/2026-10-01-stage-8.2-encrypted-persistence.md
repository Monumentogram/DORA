## Design boundaries

- Use Room and an admitted SQLCipher build for one encrypted product catalog
  and Recovery journal. Keep accepted Recovery controllers, cryptography and
  descriptor-based storage implementations unchanged and compile them in place.
- Store the database, encrypted envelopes and encrypted audio under credential
  encrypted private no-backup storage. Use a fresh random 256-bit database
  passphrase wrapped by a versioned nonexportable Android Keystore key. Separate
  first creation from reopening; absent, unavailable or invalid existing keys
  never authorize replacement. Preserve ciphertext on every open failure.
- Enforce App Lock through system authentication and a process-local revocable
  capability. Check authorization for every sensitive operation. Revoke on
  background, device lock and process death; reject stale authentication
  callbacks. Recording keys remain independent of per-use biometric binding.
- Serialize catalog, Recovery publication, extraction and deletion. Persist
  exact append/finalization intents before external publication. Treat uncertain
  transaction completion as fenced until authenticated exact reconciliation.
- Use restrictive foreign keys, no-overwrite reservations and exact ordered
  source readback. Confirm commit only after successful transaction completion.
  Deletion starts with a durable scoped tombstone, blocks new operations,
  removes only inventoried keys/artifacts and records durable retry progress.
  Retain the encrypted tombstone and source-unavailability reason.
- Prove WAL, FULL, foreign_keys=ON, wal_autocheckpoint=0 and memory-only temp
  storage for every physical connection. A stock postKey hook is insufficient:
  SQLCipher applies defaults afterwards. The proposed custom Room helper opens
  WAL with a single-connection pool, configures and verifies before schema work,
  and rejects any replacement physical connection within a helper epoch. It
  exposes no raw handles, readonly fallback, destructive migration or dynamic
  reconfiguration. Device tests must establish this before admission.
- Silence both Java and native database diagnostics before any sensitive data
  reaches the library. The published SQLCipher candidate has a native SQLite
  logging callback independent of its Java logger; source and binary inspection
  alone do not establish safe failure-path behavior. Admission requires a
  canary test and, if necessary, a provenance-verified hardened build.

Use real entities/DAOs with restrictive foreign keys and unique constraints for

prevent replay under a different identity. Preserve tombstones/namespace claims;

Implement `EncryptedAudioCatalog` and separate adapters for

All product operations must share one serialized vault lease, including future
deletion and extraction. A nested/reentrant caller may not acquire a second
logical operation. Expose a bounded internal deletion seam that records an exact
asset tombstone before mutation, freezes its run/artifact inventory, persists
remaining/completed steps and marks USER_DELETED only after caller-supplied
verified completion. File/key deletion is the parent's later integration task.
Return no paths/capabilities through public product ports.

Reserve a typed append/finalization intent durably before returning success.
After uncertain commit, preserve/reload the same intent and fence the asset.
Commit success requires successful transaction completion and exact readback;
markSuccessful alone is insufficient. Unit and manifest insertion share one
transaction. Transaction exceptions must not authorize replacement or deletion.
Reject schema/identity inconsistency, holes, conflicting replay, namespace
collision and stale expectations. Preserve immutable finalized sources.

Use TDD for deterministic behavior, real Room instrumentation where JVM cannot
prove Android transaction/schema behavior, and explicit fault injection at the
actual adapter boundary. Include concurrent-writer exclusion, intent/CAS exact
readback, tombstone blocking and transaction-end failure. No sleeps. Synthetic
data only. Record RED and GREEN commands/results; never claim unexecuted device
tests passed. Parent coordinates shared emulator/Gradle runs to avoid conflicts.
