## Design and decisions

AudioRecord (exact PCM S16LE / 16000 / mono) feeds bounded memory buffers, then
ProductAudioWriterPort and the existing encrypted vault/Recovery composition.
There is no plaintext file or second audio store. Transport units are bounded by
the existing 160000-byte bridge limit, with no VAD/rotation/overlap policy.

The service owns capture. A serialized controller owns identity, physical segment
provenance, frame accounting, confirmation and finalization. UI receives only
state, exact frame counts, normalized errors and bounded amplitude. Navigation
does not stop the controller. Pausing releases the recorder; resume creates a new
physical segment without advancing the logical frame position during the pause.

Security reconciliation: Stage 7.4 D/J explicitly admits an already user-started
recording's bounded service capability after UI lock. ADR-PERSISTENCE-002 only
implements ordinary foreground sessions. Add a separate exact-recording writer
capability inside AndroidProductAudioRuntime after real system authentication.
Ordinary sessions and all plaintext-delivery rights still revoke on background.
The service capability exposes no readers/deletion/general catalog access, cannot
create another recording, cannot survive process death, and closes after stop.
Explicit security revocation stops recording. Locked resume routes through visible
UI and fresh authentication. No release authorization override. The separately owner-authorized debug exception is recorded in ADR-DEV-001; physical acceptance disabled its marker.
